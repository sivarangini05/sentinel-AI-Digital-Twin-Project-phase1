ABSTRACT

Sentinel Twin is a local endpoint monitoring system that compares the present behaviour of a Windows computer with a behavioural reference learned from the same machine. A Python agent collects process details, CPU and memory usage, thread activity and file changes in a watched folder every 1.5 seconds and converts each reading into a ten-feature vector. Three detectors work on this vector. A digital twin built on Isolation Forest measures how far the reading has moved from the learned baseline, a Random Forest classifier gives a learned score, and a rule engine checks selected process names and bursts of activity. The three scores are combined with fixed weights into a single risk value that is placed in one of four severity bands.

A Flask dashboard with an interactive 3D view shows the live readings, the contribution of each detector, the features that changed most, and a searchable alert feed. The user can pause monitoring, reset the baseline, filter alerts and export an incident as JSON. Rules that match a reviewed list are linked to possible MITRE ATT&CK techniques, and the alert records which evidence is still missing, so a name-only match stays a hypothesis. Phase I covers the problem study, literature survey, requirements, system design, the working prototype and an analysis of the dashboard results. The Random Forest is trained on synthetic data, so its holdout scores show that the pipeline works and do not measure real malware detection. Phase II will add event-based collection, independently labelled endpoint data and durable incident storage.
